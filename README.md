# My blockchain learning workspace

I created this Hardhat 3 learning project to study Solidity and the Gnosis
Conditional Token Framework. It includes local exercises and guarded Sepolia
scripts. The CTF, test collateral, and adapter have been deployed to Sepolia,
and I have exercised the condition, split, merge, payout, and redemption flows
there. This is still practice code, not a production prediction market.

I keep my lesson notes in [`docs/`](./docs/README.md).

## Requirements

- Node.js 22.13.0 or newer
- npm 11.3.0 or newer

## Commands

I run these commands from this directory:

```powershell
npm.cmd install
npm.cmd run compile
npm.cmd test
```

I use `npm.cmd` because my Windows PowerShell execution policy blocks the
unsigned `npm.ps1` shim. If I use a terminal where `npm --version` works, I can
use the shorter `npm` form.

A successful compile tells me which Solidity compiler built each group of
files. After rebuilding both compiler versions during the Stage 4 review,
the Stage 5 local bridge test run reported 190 passing tests (164 existing plus 26 new). The local Hardhat suite uses an ephemeral
in-memory network and does not send public-network transactions. Separate
guarded Sepolia scripts can read chain state and, only when explicitly
requested with their confirmation flow, submit testnet transactions.

## Files and directories

- `package.json` defines this private npm project, its commands, and development dependencies.
- `package-lock.json` locks exact dependency versions for reproducible installs and should be committed.
- `hardhat.config.ts` loads the Viem toolbox and selects Solidity 0.8.34 for my code plus Solidity 0.5.10 for the official legacy CTF source.
- `tsconfig.json` configures TypeScript for Hardhat's ESM-based test environment.
- `contracts/` contains my question, token, CTF mock, ID, and adapter exercises.
- `test/` contains unit tests and the complete local CTF integration suite.
- `scripts/` contains local helper scripts and guarded Sepolia preflights and testnet operations.
- `docs/` contains my detailed learning notes.
- `.gitignore` excludes dependencies, generated build output, editor files, and every `.env` variant except a safe example file.
- `artifacts/` and `cache/` are generated by compilation and must not be edited or committed.

## Safety boundaries

Sepolia deployment and lifecycle notes are in
[`docs/SEPOLIA_DEPLOYMENT_PREPARATION.md`](./docs/SEPOLIA_DEPLOYMENT_PREPARATION.md)
and the related guides. Sepolia uses test ETH and test collateral, not Mainnet
funds. I keep `.env` local and ignored, and never put private keys or RPC
credentials in source files or Git.
