# Blockchain learning workspace

This is a local-only Hardhat 3 project for learning Solidity before introducing
the Gnosis Conditional Token Framework. The example contract is intentionally
small and is not production prediction-market code.

## Requirements

- Node.js 22.13.0 or newer
- npm 11.3.0 or newer

## Commands

Run these from this directory:

```powershell
npm.cmd install
npm.cmd run compile
npm.cmd test
```

`npm.cmd` avoids a Windows PowerShell execution-policy issue that can block the
unsigned `npm.ps1` shim. If `npm --version` works in your own terminal, the
shorter `npm` form is fine.

A successful compile ends with a message that the Solidity file compiled. A
successful test run reports five passing tests and zero failures. All tests use
an ephemeral in-memory Hardhat network: no public network or real funds are
involved.

## Files and directories

- `package.json` defines this private npm project, its commands, and development dependencies.
- `package-lock.json` locks exact dependency versions for reproducible installs and should be committed.
- `hardhat.config.ts` loads the Viem toolbox and selects Solidity 0.8.34 with optimization.
- `tsconfig.json` configures TypeScript for Hardhat's ESM-based test environment.
- `contracts/QuestionRegistry.sol` is the practice smart contract.
- `test/QuestionRegistry.ts` checks successful behavior and expected failures.
- `.gitignore` excludes dependencies, generated build output, editor files, and every `.env` variant except a safe example file.
- `artifacts/` and `cache/` are generated by compilation and must not be edited or committed.

## Safety boundaries

There is no public-network configuration, deployment script, CTF dependency,
or private key in this project. Never put secrets in Solidity, configuration,
tests, or Git. A future `.env` file remains local and ignored.
