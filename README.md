# My blockchain learning workspace

I created this local-only Hardhat 3 project to learn Solidity step by step and
then understand the Gnosis Conditional Token Framework. I keep each example
small so I can understand the code instead of only copying it. This is practice
code, not a production prediction market.

I keep my lesson notes in [`docs/`](./docs/README.md).

## Requirements

- Node.js 22.13.0 or newer
- npm 11.3.0 or newer

## Commands

I run these commands from this directory:

```powershell
npm.cmd install
npm.cmd run compile
npm.cmd test
```

I use `npm.cmd` because my Windows PowerShell execution policy blocks the
unsigned `npm.ps1` shim. If I use a terminal where `npm --version` works, I can
use the shorter `npm` form.

A successful compile tells me which Solidity compiler built each group of
files. My latest full test run reports 37 passing tests and zero failures. All
tests use an ephemeral in-memory Hardhat network, so no public network or real
funds are involved.

## Files and directories

- `package.json` defines this private npm project, its commands, and development dependencies.
- `package-lock.json` locks exact dependency versions for reproducible installs and should be committed.
- `hardhat.config.ts` loads the Viem toolbox and selects Solidity 0.8.34 for my code plus Solidity 0.5.10 for the official legacy CTF source.
- `tsconfig.json` configures TypeScript for Hardhat's ESM-based test environment.
- `contracts/` contains my question, token, CTF mock, ID, and adapter exercises.
- `test/` contains unit tests and the complete local CTF integration suite.
- `docs/` contains my detailed learning notes.
- `.gitignore` excludes dependencies, generated build output, editor files, and every `.env` variant except a safe example file.
- `artifacts/` and `cache/` are generated by compilation and must not be edited or committed.

## Safety boundaries

I do not use public-network configuration, deployment scripts, real funds, or
private keys in this project. I will never put secrets in Solidity,
configuration, tests, or Git. A future `.env` file must remain local and
ignored.
